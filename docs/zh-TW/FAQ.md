# 常見問題

## 為什麼啟動後沒有自動開啟瀏覽器？

`gbabeldocui` 只會啟動服務，不會開啟瀏覽器。請手動前往 `http://127.0.0.1:7860/login.html`。

## 為什麼在本機透過 HTTP 登入後又回到登入頁？

預設會啟用 Secure Cookie。本機回環 HTTP 必須在啟動前設定 `GBABELDOCUI_COOKIE_SECURE=false`；公開部署必須使用 HTTPS，並將其維持為 `true`。

## 為什麼無法從遠端建立第一個管理員？

預設只允許從本機初始化。可信環境確實需要遠端初始化時，請設定一次性高強度 `GBABELDOCUI_SETUP_TOKEN`，完成後立即移除並重新啟動服務。

## 多個 worker 或容器能否共用同一個資料目錄？

不能。每個 `data/` 目錄只允許一個程序與一個副本；第二個執行個體會立即失敗，以免破壞任務狀態。

## 服務重新啟動後，任務會如何處理？

任務狀態與歷史記錄儲存在 SQLite。啟動時會結束未完成任務，已完成、失敗與已取消記錄會依保留期限清理。

## 為什麼重新開啟設定後，API 金鑰顯示為空白？

已儲存的金鑰不會傳回瀏覽器。留空後儲存表示保留原金鑰；只有填入新值才會取代原值。

## 上傳檔案與翻譯結果儲存在哪裡？

預設位於 `data/users/<username>/`。其中可能包含金鑰與私人文件，禁止提交或公開。

## 如何更新？

原始碼安裝請先執行 `git pull --ff-only`，再執行 `uv sync --frozen`；Compose 部署更新原始碼後，執行 `docker compose up -d --build`。進行重大操作前，應先停止服務並備份受保護的資料目錄。

## 為什麼上傳時會傳回 HTTP 413？

請求超過 `GBABELDOCUI_MAX_UPLOAD_BYTES` 或串流請求本文上限。提高限制也會增加儲存與處理風險，公開部署時應維持明確上限。
