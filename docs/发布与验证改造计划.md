# 发布与验证改造计划

## 目标

将 `G:\GBabelDocUI` 整理为可独立维护、可本地提交和后续发布到公开 GitHub 的主项目；保留 `data/` 作为后续验证数据，但不让数据库、PDF、用户配置、密钥或运行时目录进入 Git 历史和 Docker 构建上下文。

## 阶段进度

### 阶段一：仓库边界与来源声明

- 当前进度：已完成。
- 已完成：初始化本地 `main` 分支；保留 `data/` 原位不删除、不移动；补充 Git/Docker 忽略规则；添加本文件和 `NOTICE`；将主项目元数据指向 `eaiu/GBabelDocUI`。
- 关键决策：不设置远程仓库、不访问 GitHub、不推送；`yuan/` 仅作本地来源对照并排除；`uv.lock` 用于依赖复现并允许进入 Git。
- 必需笔记：当前本地 Git 用户身份已配置；`data/` 中存在真实运行数据和敏感配置，必须通过 `git check-ignore` 与 `git ls-files` 双重核验。

### 阶段二：运行边界修复

- 当前进度：已完成。
- 已完成：验证并限制上传文件名、文件 ID 和文件大小；拒绝越界用户名；移除日志中的完整用户配置；将 CORS 改为显式环境变量配置；固定 `pdf2zh-next`/`BabelDOC` 版本并生成 `uv.lock`；移除 Docker 构建中的随机缓存破坏和无界升级。
- 后续注意事项：不改变现有验证数据；不在代码、测试输出或提交信息中记录 API 密钥、会话令牌和密码哈希。

### 阶段三：测试与提交前审计

- 当前进度：已完成。
- 已完成：主项目测试 53 passed；`ruff check gbabeldocui tests` 通过；`uv lock --check` 通过；`python -m compileall` 通过；`uv build` 成功生成源代码包和 wheel；预演 `git add` 未包含 `data/`、`yuan/`、数据库、PDF、本地环境和缓存。
- 已完成：允许发布的 291 个项目文件已创建本地中文初始提交；提交后复核远程为空，运行时数据仍由忽略规则排除。
- 后续注意事项：`yuan/` 自身是独立 Git 仓库，运行测试时只指定主项目测试目录，避免同名测试模块冲突。

### 阶段四：GitHub Actions 镜像发布

- 当前进度：工作流已连接公开仓库 `SocialYjj/GBabelDocUI`；`main` 分支推送、`v*` 标签推送和手动运行都会执行云端构建，Pull Request 只构建并扫描。
- 已完成：新增并验证 `.github/workflows/docker-publish.yml`；发布事件会登录 GHCR，并发布 `latest`、版本号（仅版本标签）和提交短 SHA 标签。
- 关键决策：镜像名称按 `GITHUB_REPOSITORY` 转为小写，避免项目仓库名称中的大写字母违反 Docker 镜像命名规则；发布前阻止可修复的 `CRITICAL/HIGH` 漏洞。
- 数据边界：工作流使用仓库根目录作为 Docker 构建上下文，但现有 `.dockerignore` 排除了 `data/`、`yuan/`、数据库、PDF、虚拟环境和缓存；这些内容不会进入镜像或 Git 提交。
- 必需笔记：工作流发布前仍由 Trivy 阻止可修复的 `CRITICAL/HIGH` 漏洞；首次 `main` 推送后需在 GitHub Actions 中检查云端构建和 GHCR 包可见性。

### 阶段五：全项目审计与 WSL 隔离验证

- 当前进度：代码修复、历史内容清理和 WSL/Docker 验证已完成，准备进行最终回归与提交前审计。
- 执行顺序：先盘点和建立基线，再使用临时运行数据在 WSL 部署，最后只修复已复现问题并清理确认无用的生成物。
- 数据约束：不删除、不移动、不改写 `data/`；WSL 使用独立临时数据目录；不将 `data/`、`yuan/`、数据库、PDF、密钥或用户配置加入 Git。
- 清理约束：只处理确认属于缓存、临时构建产物或死文件的内容；`.git/`、源代码、测试、文档、`uv.lock` 和当前本地运行环境默认保留。
- 变更约束：不访问 VPS、不配置远程、不推送 GitHub；发现需要跨模块重构或改变既有行为时，先记录证据并停止扩展修改。
- 验收标准：在可用的 WSL 环境中通过测试、静态检查、构建和 HTTP smoke test；Windows 侧完成 Git、YAML、忽略边界审计；Git 差异只包含本阶段确认的修改；真实 `data/` 文件数量和字节数未减少。
- 盘点事实：清理前 Git 跟踪 292 个文件；`data/` 为 6 个文件、6,173,588 字节；`.venv` 是指向 Linux `/usr/bin` 且缺少可执行目录的失效环境，`dist/`、`.pytest_cache/`、`.ruff_cache/` 和 `.workbuddy/` 是未跟踪本地产物；`script/` 与 `test/test_cache.py` 已确认没有被当前发布链路引用并删除。
- 基线事实：Windows 系统 Python 缺少项目依赖；`uv run` 受失效 `.venv` 的 `lib64` 链接阻塞，当前 Windows 测试结果不能作为有效通过基线，改由 WSL 临时环境复现。
- WSL 验证事实：在 Ubuntu-24.04 的临时环境 `/tmp/gbabeldocui-validation-venv` 中安装锁定依赖后，清理前 61 个测试通过，删除历史测试后当前项目 56 个测试通过；Ruff、编译检查和 `uv.lock` 校验均通过；使用临时数据目录完成了根页面、静态资源、首次设置、登录令牌和设置读取的 HTTP smoke test。
- 已复现问题：SQLite 未启用外键时删除用户会留下可继续验证的旧会话；传入自定义数据库路径时用户目录仍写入全局 `DATA_DIR`；注册开关接口接受字符串等非布尔值；设置导入在大小检查前一次性读取整个上传文件。
- 清理事实：已删除失效的 `.venv`、`dist/`、`.pytest_cache/`、`.ruff_cache/`、`.workbuddy/` 和 Python `__pycache__`；未删除或移动 `data/`，也未改动 `yuan/`（当前不存在）。
- 修复事实：统一 SQLite 连接的外键和超时设置；删除用户后令牌立即失效；自定义数据库路径与用户文件目录保持一致；注册开关使用严格布尔输入；设置导入只读取上限加 1 字节；持久化 JSON 统一使用 UTF-8；时间戳改为兼容现有格式的 UTC 生成方式；FastAPI 启停改用 lifespan，去除本项目产生的弃用警告。
- Docker 验证事实：WSL Docker 构建成功，构建上下文约 1.29 MB，优化前镜像约 905,908,840 字节，优化后约 808,995,150 字节；通过 Docker 容器根页面、静态资源和认证状态 smoke test。构建时 BabelDOC 资源下载出现可重试网络警告但最终成功，离线资源缓存策略留作后续独立改造。

- 本轮不清理或重建 `data/`，不删除历史 PDF、翻译结果、数据库和用户配置。
- 当前翻译任务状态仍由进程内 `active_tasks` 管理；服务重启后的任务恢复属于后续独立改造，不在本轮以兼容补丁处理。
